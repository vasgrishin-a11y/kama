# Запуск КАМА

## Локальный Node.js

Требуется Node.js 24.x (также указан в .nvmrc и package.json).

```sh
npm ci
cp .env.example .env
# Отредактируйте .env для своего окружения.
node --env-file=.env server.js
```

Откройте http://localhost:8080. Команда npm start использует уже экспортированные переменные окружения; сама файл .env не читает. Логины и пароли вводятся в форме подключения и не включаются в образ или репозиторий.

## Docker Compose

```sh
cp .env.example .env
# Настройте PGHOST/PGPORT, CH_HOST и другие параметры.
docker compose up --build -d
docker compose logs -f kama
```

Контейнер запускается непривилегированным пользователем, с файловой системой только для чтения. Порт опубликован только на 127.0.0.1; для удалённого доступа используйте HTTPS reverse proxy с аутентификацией вашей организации. Встроенного входа пользователей у приложения нет. В CORS_ORIGINS укажите публичный HTTPS origin прокси. Не открывайте backend напрямую в интернет.

`localhost` внутри контейнера означает сам контейнер. PGHOST должен указывать на реальный доступный контейнеру адрес БД. Compose не создаёт PostgreSQL или ClickHouse и не загружает данные. Для внутреннего центра сертификации смонтируйте PEM-файл CA и задайте NODE_EXTRA_CA_CERTS; не помещайте закрытые ключи в образ.

## Параметры

| Переменная | По умолчанию | Назначение |
|---|---|---|
| HOST / PORT | 0.0.0.0 / 8080 | Адрес прослушивания Node; .env.example ограничивает локальный запуск 127.0.0.1 |
| KAMA_PORT | 8080 | Локальный опубликованный порт Compose |
| PGHOST / PGPORT | localhost / 5432 | PostgreSQL и значения формы подключения |
| PGDATABASE | pgs_app_data_db | База входного спроса |
| PG_METADATA_DATABASE | pgs_app_metadata_db | База имён сценариев |
| PG_ALLOWED_TARGETS | PGHOST:PGPORT | Разрешённые пары host:port через запятую; проверяются до подключения |
| CORS_ORIGINS | пусто | Дополнительные origins через запятую, без завершающего слеша; `*` не используется |
| ALLOW_INSECURE_PG | false | Только явное true разрешает выбранные пользователем режимы off/insecure |
| CH_HOST / CH_PORT / CH_PROTO | пусто / 443 / https | Значения формы ClickHouse, доступного браузеру |
| NODE_EXTRA_CA_CERTS | не задано | PEM доверенного внутреннего CA |

Сервер передаёт в /assets/runtime-config.js только публичные настройки адресов и баз, без паролей. При статическом размещении этот файл содержит пустую конфигурацию: адреса задаются в форме. PostgreSQL при таком размещении требует отдельного Node backend и разрешения origin в CORS_ORIGINS. Для file:// origin равен `null`; предпочтительнее запускать Node и открывать его страницу вместо разрешения `null`.

## Поведение соединений

- TLS PostgreSQL по умолчанию проверяет сертификат. Старый режим auto теперь означает strict без скрытого перехода к plaintext.
- Сессии PostgreSQL и ClickHouse хранятся в sessionStorage текущей вкладки, TTL — 4 часа бездействия. Старые записи с паролями из localStorage удаляются при загрузке. Настройки интерфейса и профили без паролей остаются в localStorage.
- sessionStorage не является шифрованным хранилищем: код этого origin имеет к нему доступ; браузер может восстанавливать вкладки. На общих компьютерах используйте «Забыть сессию» и закройте вкладку.
- Backend раздаёт только assets/ и редирект с `/` на каноническую страницу. Документы, тесты, .env, server.js и зависимости через HTTP недоступны.
- Списки разрешённых origins и адресов БД не заменяют аутентификацию и сетевые политики. Ограничьте исходящие соединения backend к разрешённым БД.
- Google Fonts удалён: шрифт Manrope подключается локальными файлами `assets/fonts/*.woff2` через `@font-face`, локальный SheetJS не требует CDN.

## Проверка после развёртывания

1. Откройте /api/health и главную страницу; проверьте загрузку assets/.
2. Подключите ClickHouse из браузера, выберите версию плана и гранулярность.
3. Подключите PostgreSQL; сопоставьте версии CH со схемами PG, проверьте названия сценариев.
4. Сверьте контрольный объём independent_demand, покрытие, выручку и маржу с эталонным расчётом бизнеса.
5. Проверьте TLS, доступ через HTTPS и поведение «Забыть сессию».

Реальные соединения и бизнес-сверка требуют доступа к контуру КАМА и выполняются владельцем окружения; автоматические тесты используют подмену DB-слоя.

### GitHub Pages

Pages публикует корень ветки `main` в подпапку `/<repo>/` и не запускает `server.js`, редиректа с `/` там нет:

- новый интерфейс — `https://vasgrishin-a11y.github.io/kama/assets/kama.html` (ссылки внутри `kama.html` относительные, поэтому они разрешаются внутри подпапки);
- `https://vasgrishin-a11y.github.io/kama/` — корневой `index.html`, редирект (`meta refresh` + `location.replace`) на `./assets/kama.html`;
- исторический интерфейс коннекторов — `https://vasgrishin-a11y.github.io/kama/legacy.html`;
- сборка Pages запускается push-событием в `main`. Если после merge сайт не обновился, сравните SHA последней сборки (`GET /repos/<owner>/<repo>/pages/builds/latest`) с `main` и запросите пересборку в Settings → Pages → «Request a build».

## CI

.github/workflows/ci.yml запускает npm ci и npm test на Node.js 24, а также сборку Docker-образа и HTTP-проверку контейнера. Workflow работает на PR, push в main и вручную. Обязательность успешных проверок перед merge настраивается владельцем в branch protection/rulesets GitHub.
