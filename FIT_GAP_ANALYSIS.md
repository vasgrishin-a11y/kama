## Совместимость

Бизнес-формулы, таблицы и API-маршруты сохранены. Идентификатор API `inplan-dashboard` и ключи настроек интерфейса оставлены для совместимости существующих коннекторов. In.Plan указан как основа продукта, а не адрес репозитория.

При обновлении требуется повторно ввести пароли соединений: прежние постоянные сессии удаляются. Для PostgreSQL с частным CA настройте NODE_EXTRA_CA_CERTS; отключение проверки TLS больше не происходит автоматически. Для HTTPS reverse proxy задайте его публичный origin в CORS_ORIGINS. Адреса БД исходного проекта не подставляются.

## Проверка и границы

Добавлены восемь проверок адаптации: ограниченная раздача файлов и runtime-конфигурация; запрет/разрешение origin; запрет посторонних PostgreSQL targets и слабых TLS-режимов до вызова DB-слоя; отсутствие TLS downgrade; переменные окружения; сессии PostgreSQL и ClickHouse, TTL и удаление старых паролей.

Проверено на Node.js v24.19.0: npm ci по lock-файлу выполнен успешно; npm test — 182 passed, 0 failed, 0 skipped (около 32 секунд). YAML CI и Compose синтаксически разобраны. Живые PostgreSQL/ClickHouse, бизнес-показатели на данных КАМА и визуальная приёмка в настоящем браузере не проверялись. Docker недоступен в локальной среде; сборка и smoke-test образа поручены GitHub Actions. CI не равнозначен включению обязательных проверок в настройках защиты main.

Это техническая адаптация репозитория. Она не подменяет бизнес-ТЗ, аудит безопасности, настройку SSO, сертификатов и сети в рабочем контуре.
